# 검증 체크리스트

제출하거나 공유하기 전에 이 체크리스트로 확인합니다.

## 문제와 사용자

- [ ] 해결하려는 문제가 한 문장으로 분명합니다.
- [ ] 대상 사용자가 명확합니다.
- [ ] 30~60분 안에 mock data로 테스트할 수 있는 작은 범위입니다.
- [ ] 한 번의 답변이 아니라 반복 가능한 지식 업무를 다룹니다.

## 입력

- [ ] 입력 형식이 분명합니다.
- [ ] mock data가 있습니다.
- [ ] 실제 민감 정보가 포함되어 있지 않습니다.
- [ ] secret, token, password, real API key가 포함되어 있지 않습니다.

## 출력

- [ ] 출력 형식이 분명합니다.
- [ ] 비개발자도 이해할 수 있는 결과입니다.
- [ ] 검토가 필요한 산출물은 draft로 표시됩니다.
- [ ] `result.json`에 status, outputs, warnings, metrics, next improvements가 기록됩니다.

## Workflow

- [ ] YAML은 특정 runtime에 묶이지 않습니다.
- [ ] 각 단계가 쉬운 말로 작성되어 있습니다.
- [ ] 각 단계에 input과 output이 있습니다.
- [ ] human approval point가 포함되어 있습니다.
- [ ] 첫 테스트에 외부 서비스가 필요하지 않습니다.

## 안전

- [ ] workflow는 mock data만 사용합니다.
- [ ] 파괴적인 작업을 허용하지 않습니다.
- [ ] 게시, 메시지 전송, 시스템 변경은 사람의 승인이 필요합니다.
- [ ] 의료, 법률, 금융 같은 전문 판단은 피하거나 교육용 mock example로 제한합니다.

## Skillathon 제출 준비

- [ ] `README.md`가 문제 정의, 실행 방법, 결과물, 검증 결과, 한계를 설명합니다.
- [ ] `SKILL.md`가 같은 업무를 다시 실행할 수 있는 절차, 입력/출력, guardrails를 설명합니다.
- [ ] `references/`에 체크리스트, 설계 노트, 긴 설명 자료가 분리되어 있습니다.
- [ ] `mock-data/` 또는 샘플 입력이 있습니다.
- [ ] 적어도 하나의 완성 예시에 `intent.md`, `workflow.yaml`, `result.json`이 있습니다.
- [ ] 제출 설명을 3문장 안에 말할 수 있습니다.
